# Sprint 15 clock-path decision

The decision for the current workstation is **no viable acceptance clock path**. Acceptance-v1 remains frozen at a maximum 100 ms independent UTC uncertainty. The prior multi-reference trial's best defensible bound was 308 ms. The current inspection is materially worse: Windows Time reports unsynchronized state, an approximately 196 ms phase offset, almost 8 seconds root dispersion, and a failed resync. The host is a battery-powered portable computer on Wi-Fi, with no wired adapter active. These conditions do not permit a qualifying prospective start.

No independently administered alternative host with demonstrated reliable power, wired connectivity, private storage, and sub-100 ms UTC evidence is available in the project inventory. Moving the collector to an unverified machine would change the failure location rather than certify it. The exact dependency is an operator-controlled always-on host on reliable AC and preferably wired networking, followed by a fresh, retained, multi-reference clock measurement that satisfies the frozen bound.

The calibrated research clock in `src/research/calibrated_clock.py` is deliberately inactive. Each observation's reference-UTC interval is projected to the newest common monotonic anchor before intersection, with oscillator drift added across the projection interval. The candidate then defines forward monotonic propagation, further drift expansion, expiry, and invalidation after sleep or a wall-clock step. It rejects nonfinite configuration/timestamps, stale reference observations, and fewer than two independently administered reference families. Raw host and provider timestamps remain outside this derived interval. It cannot make the present measurements pass, does not retroactively qualify captured data, and has no runtime adapter. Activation would require a separately approved `research-calibrated-clock-v2` protocol and a new prospective cohort; it must never be enabled after looking at cohort results.

Historical warm-up recovery is independent of the clock failure. The authenticated DEMO Desktop helper produced 220 validated, paired, completed EUR/USD bid/ask H1 candles with warm-up-only provenance and expected weekend gaps. This satisfies the indicator seed dependency but does not count toward the five-day live-source acceptance cohort. The acceptance counter therefore remains zero days, and paper evaluation remains prohibited.

## Proposed prospective research-calibrated-clock-v2 (inactive)

For H1 paper research only, a separately approved v2 could use the candidate interval mathematics with predeclared operating rules: observations from at least two independently administered UTC families; quantified reference and network uncertainty; projection to one monotonic anchor with a pre-measured oscillator drift bound; a 30-minute maximum observation age and calibration expiry; and immediate invalidation on sleep, clock discontinuity, reference disagreement, or loss of continuity. Raw provider time, raw host UTC, host monotonic time, reference observations, and the derived UTC interval must be stored as separate fields.

A proposed maximum derived half-width is 250 ms. Quote age would be an interval, not a point: an observation is eligible only when its entire age interval lies inside the frozen −100 to +2,000 ms range, and the delivery p99 test uses the conservative upper endpoint and must remain at most 1,000 ms. The 250 ms proposal is not acceptance-v1 and is not approved or activated. Its reference uncertainty model, network asymmetry allowance, oscillator bound, clock-step detector, and operating implementation still require independent review and prospective synthetic/field validation before any cohort starts.
