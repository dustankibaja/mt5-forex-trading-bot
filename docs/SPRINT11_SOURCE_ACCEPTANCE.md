# JForex DEMO source acceptance

Use the [official Dukascopy Bank DEMO form](https://www.dukascopy.com/swiss/english/forex/demo-fx-account/), JForex, after the provider confirms Tanzania DEMO and SDK access. The public form is reachable and shows contact fields and CAPTCHA; rendering the form does not prove residency eligibility. The user must decide whether to accept terms and submit the form. Use local Windows Credential Manager for issued credentials. Never place them in arguments, logs or the repo.

Use the [standalone Java SDK](https://wiki.dukascopy.com/en/development/get-started-api/use-jforex-sdk/download-jforex-sdk) with a pinned vendor SDK and its compatible JDK. Subscribe to EUR/USD; an isolated Java process should pass read-only observations to Python via a bounded queue or local file, without exporting credentials. The [tick interface](https://www.dukascopy.com/client/javadoc3/com/dukascopy/api/ITick.html) gives best bid/ask and inherits timed-element time; confirm UTC epoch milliseconds against provider output and corroborated host UTC. The documentation does not guarantee quote-generation latency, delivery completeness, or a provider sequence. Record a local monotonic sequence, explicit dropped counts and reconnect boundaries; do not infer perfect delivery from consecutive local sequence numbers.

Capture provider time, callback UTC and monotonic time before queueing, source and environment, connection epoch, local sequence, instrument, both sides, and transport connect/disconnect/heartbeat events. Persist original data separately from derived events. On disconnect or queue overflow invalidate current marks, record the gap and re-subscribe after bounded backoff. Do not backfill a missing prospective quote with history. A heartbeat does not replace a fresh tick.

Proposed acceptance gate, before any paper freeze: verify host UTC against an independent reference with ≤100 ms uncertainty; measure receipt minus provider time and distribution by session across five trading days and at least one controlled reconnect. Treat future age beyond host uncertainty, age >2 s, crossed/invalid quotes and backward provider timestamps as ineligible. Record same-time quotes with changed prices; count identical observations separately from journal-event ID retries. Measure interarrival and queue delays and confirm no unexplained loss during the experiment. Require p99 nonnegative delivery age ≤1 s in the intended trading window; report the fraction rejected. Stop decisions on gaps and do not silently carry forward stale quotes.

Use completed paired bid/ask H1 bars (or validate the bars built from observed ticks against the paired [onBar callback](https://www.dukascopy.com/client/javadoc/com/dukascopy/api/IStrategy.html)). Reject uncertain/missing paired bars. [JForex history](https://www.dukascopy.com/wiki/en/development/strategy-api/historical-data/overview-historical-data/) documents live-origin history and distinct real-time DEMO prices. Use live-origin history only as labeled warm-up; rebuild or compare indicators over DEMO-only completed bars before treating input as equivalent. Establish at least 211 completed DEMO H1 bars for that comparison. Preserve UTC session rules and next executable side. Freeze source, strategy, risk and execution hashes, costs, gap behavior, and future start before recording any evaluation. A baseline candidate would use the unchanged Compression Release signal, ≤0.25% risk, no broker order route, and a preregistered prospective cohort of at least six months and 50 closed trades before judging expectancy, drawdown or cost robustness. This is a proposed gate, not a deployed freeze.
